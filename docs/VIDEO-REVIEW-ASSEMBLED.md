# Формат «Видеообзор рынка v2» — режим `assembled` и план выпуска

**Статус:** внедрено в ветке `feature/video-review-v2` (от `main`/тега `pre-video-review-2026-11-02`).
Старое поведение пайплайна не менялось: без новых флагов всё работает как раньше (последний
прогон `2026-10-19-обзор-рынка` — приёмка 8/8 + 9/9).

## Что нового в формате

- OBS пишет **одно видео** (композит): сцены `FACE` (ведущий полностью), `CIRCLE` (ведущий в кружке
  поверх графики), `CHARTS` (только графики) переключаются вживую. Монтаж **не перекомпоновывает
  камеру**: никакого split/кружка/маски не строится, дубль уже сведён.
- План выпуска (`plan.json`, генерирует дашборд «🎬 Видеообзор»): блоки, сцены, TV-layout'ы
  (`L1_US` / `L2_RU` / `L3_CRYPTO` / `L4_STORY`), read/comment, «что показать в TradingView»,
  rationale «почему так сняли», планируемые длительности.
- Графика/вставки берутся из `script.md`, как и раньше (формат `#N…~сек` + narration + `🎞 B-roll`).
  План добавляет к блокам сцены и правила безопасных зон.
- Проверка «графика не на лице» в режиме `assembled` **отключается**: в OBS-композите лицо уже
  переставлено/в кружке, единая face-рамка неприменима. Правила зон — в `edit/video_plan.json`.

## Запуск

```powershell
cd D:\LLM\video-montage-template

py -3 scripts\montage.py --label 2026-11-04-среда-динамика `
  --take "takes\2026-11-04 13-00-00.mp4" `
  --script "script\2026-11-04-среда-динамика.md" `
  --plan "script\2026-11-04-среда-динамика-plan.json" `
  --assembled --transcribe
```

Новые флаги:

| Флаг | Что делает |
|---|---|
| `--plan <plan.json>` | добавляет стадию `video_plan`: сверка блоков, карта сцен, безопасные зоны, отчёт «план vs факт» |
| `--assembled` | означает «вход — OBS-композит»: проверка лица в `verify_extra` → SKIP, в паспорт пишется `assembled: true`, `graphics_mode: scene_safe_zones`; требует `--script` |

Без `--plan` стадия `video_plan` не появляется в пайплайне; без `--assembled` всё как раньше.

## Артефакты стадии `video_plan` (в `runs/<label>/edit/`)

| Файл | Что внутри |
|---|---|
| `video_plan.json` | блоки плана: n, сцены, TV-layout'ы, planned/actual, статус «найден в дубле», возможные дубли, rationale; `scene_ranges`, `scene_time_s`, правила `safe_zones` для FACE/CIRCLE/CHARTS |
| `plan_vs_fact.json` | машинный отчёт: план vs таймлайн vs фактическая речь, средний/максимальный сдвиг границ, found/total блоков, найденные пересъёмки, предупреждения |
| `plan_report.md` | человеческий отчёт (дописывается в конец `report.md`): таблица «блок / сцена / план / факт / сдвиг / match / дубли», карта сцен, правила зон, как это использовать при монтаже |

## Безопасные зоны графики по сценам

| Сцена | Где можно рисовать | Что не трогать |
|---|---|---|
| `FACE` | только боковые колонки (`left_outer`, `right_outer`) | лицо и центр кадра |
| `CIRCLE` | углы (`top_left`, `top_right`, `bottom_left`) | центр (там ведущий в кружке) |
| `CHARTS` | шире: левая колонка, нижняя полоса, верхний правый угол | верхнюю панель TradingView и правую ось цен |

MVP: правила фиксируются в `video_plan.json`/отчёте; генератор вставок читает их и раскладывает
карточки по сценам (см. «Сцен-зависимые раскладки» ниже).

## Сцен-зависимые раскладки вставок (P2.1)

`generate_comp_plan.py --assembled` читает `edit/video_plan.json` (его пишет стадия `video_plan`)
и кладёт каждую карточку в безопасную зону сцены, которая в этот момент на экране. Без
`--assembled` (и без `--plan`) поведение прежнее — старые боковые колонки, байт-в-байт тот же план.

| Сцена | Что делает генератор | Куда ставит карточки |
|---|---|---|
| `FACE` | как раньше | боковые колонки `left:5%` / `right:5%`, лицо не трогается |
| `CIRCLE` | углы вдали от кружка | `sc_circle_tl` / `sc_circle_tr` / `sc_circle_bl` (ширина 560–600 px), поворот по карточкам |
| `CHARTS` | площадь графика используется шире | `sc_charts_left` (800 px, левая колонка), `sc_charts_right` (700 px, с отступом от оси цен), `sc_charts_bottom` (1100 px, нижняя полоса) |

- Широкие карточки (`table/timeline/checklist/diagram/scenario/chart/…`) чередуются
  left ↔ right по всему выпуску; компактные (`stat/chips/quote/counter/miners`) уходят в нижнюю полосу.
- Копирайт-фиттер получает реальную ширину карточки, поэтому текст переносится под новый размер
  (без обрезки и многоточий).
- `CIRCLE`: по умолчанию кружок ведущего считается в **правом нижнем** углу (`passport.circle_corner`
  в `edit/data.json`, значения `tl|tr|bl|br`); карточки ставятся в три других угла.
- `outro` (блок подписки) в режиме `assembled` больше не двигает камеру: он рисуется обычной
  карточкой `sc_*` в безопасной зоне. `stage.json` содержит только `glass`-окна разделителей —
  они заодно маскируют живые переключения сцен OBS.
- В `comp_plan.json` у каждой вставки теперь есть `scene` и `layout` — монтажный агент видит,
  почему карточка стоит именно там; `meta.scene_map` содержит карту «блок → сцена».

Проверка (2026-11-02, тестовый дубль 19 октября + карта сцен): 45 вставок, классический режим
совпадает с прежним планом байт-в-байт (regression), в `assembled` 17 вставок получили
сцен-раскладки (CHARTS ×14, CIRCLE ×3), снятые кадры — `runs/vr-p21/preview/`.

## Пересъёмки и «план vs факт»

`video_review_plan.py` сверяет блоки плана с `script_plan.json` (сделанным по расшифровке):

- `located` — блок нашёлся в дубле; `match_score` — насколько текст совпал с планом;
- `shift_s` — фактическое начало блока против планового (накопительно; в таблице отчёта видно, где
  импровизация «съела» время);
- предупреждение, если фактическая длина блока отличается от плана больше чем на 30% (и >15 с);
- **дубли**: для каждого блока берутся первые значимые слова его read-текста и ищутся все вхождения
  в расшифровке; если фраза встречается больше одного раза — блок помечается `possible_retake`
  с таймкодами, в монтаж брать последний удачный дубль.
