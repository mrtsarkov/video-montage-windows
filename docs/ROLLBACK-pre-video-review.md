безопасные зоны по сценам) фиксируем стабильную версию, чтобы иметь возможность откатиться.

Тег и ветка указывают ровно на рабочее состояние, на котором собран последний ролик
(`runs/2026-10-19-обзор-рынка/out/final.mp4`, приёмка 8/8 + 9/9).

## Как откатиться

```powershell
cd D:\LLM\video-montage-template

# посмотреть, что зафиксировано
git fetch --tags
git log --oneline -1 pre-video-review-2026-11-02

# вариант 1: откатить main на стабильный тег (жёстко, как было)
git checkout main
git reset --hard pre-video-review-2026-11-02

# вариант 2: посмотреть/сравнить без изменения main
git checkout stable/pre-video-review-2026-11-02
# или: git switch -c rollback-pre-video-review pre-video-review-2026-11-02

# вернуться к новой работе
git checkout main
```

**Важно:** в git не лежат `takes/`, `runs/`, `.media/` (сырые дубли и результаты прогонов) —
откат кода не удаляет и не восстанавливает их. Перед экспериментами новые дубли лучше
не перезаписывать; при необходимости делать копию папки `takes/` вручную.

## Что изменится после (для контекста)

Планируемые доработки в ветке `feature/video-review-v2` (или серии веток):
- режим **`assembled`** — вход уже собран OBS (сцены FACE/CIRCLE/CHARTS переключаются вживую),
  монтаж не перекомпоновывает камеру: трим/аудио/оверлеи/sfx/финал/приёмка;
- чтение **`script/<label>-plan.json`** (сцены по блокам, TV-layout'ы, read/comment, rationale);
- безопасные зоны вставок **по сценам** (FACE / CIRCLE / CHARTS) вместо одной face-рамки;
- отчёт «план vs факт» (какие блоки пересняты, что вырезано и почему).

До появления этих изменений пайплайн работает ровно как раньше — тег гарантирует возврат.
