# Тексты вставок: как из сценария получается кадр

Документ про пункт «мусор из сценария попал во вставки»: почему это происходило и
как устроен слой текста, который это чинит.

## Что было не так

Сценарий — производственный документ, в нём есть служебная разметка:

```
#1Хук: правила яснее, цена ниже~50 сек
…
🎞 B-roll: Монтаж: титр «КРИПТА НА БАЛАНСЕ — МОСКВА, 15.10.2026» + справа виджет котировок BingX: BTC 81 174 (-2.38%)
```

Первая версия генератора брала `block["title"]` как есть и печатала его в кадр
(`#1Хук: правила яснее, цена ниже`), а если у компонента не было содержимого —
подставляла этот же заголовок единственной плашкой. Так в кадр попали `Хук:`,
`CTA`, `Bull-сценарий:`, названия B-roll-строк и перечисление того, что «должно
быть на экране».

## Как устроено теперь

Три слоя, каждый проверяется отдельно.

### 1. Чистка разметки (`insert_copy.py`)

`strip_markup` / `human_title` убирают номера блоков, метку `🎞 B-roll:`,
`Монтаж:`, `титр`, производственные префиксы (`Хук:`, `CTA`, `Итог`) и
переписывают сценарный ярлык сценария в читаемый:

| в сценарии | в кадре |
|---|---|
| `#1Хук: правила яснее, цена ниже` | `Правила яснее — цена ниже` |
| `#8Bull-сценарий: легальный мост` | `Бычий сценарий: легальный мост` |
| `#9Bear-сценарий: комплаенс как фильтр` | `Медвежий сценарий: комплаенс как фильтр` |
| `#12CTA` | `Что дальше` |
| `🎞 B-roll: Скрин анонса…, титр со списком спикеров: Минфин / ЦБ / АБР / ВЭБ.РФ` | `В ЗАЛЕ` + `Минфин`, `Банк России`, `Ассоциация банков России`, `ВЭБ.РФ` |

Плюс словарь опечаток распознавания (`ВБРФ` → `ВЭБ.РФ`, `комплайенс` →
`комплаенс`, `Старкнет` → `Starknet`, `арбитром` → `Arbitrum`), чтобы расшифровка
не попадала в кадр в сыром виде.

### 2. Авторский слой под прогон

`script/<метка>-inserts.json` — необязательный файл: заголовок блока (для
перебивки), кикер и содержимое каждой вставки. Генератор подхватывает его
автоматически, если файл есть, и печатает источник в отчёте. Схема:

```json
{
  "blocks": {
    "1": {
      "title": "Правила яснее — цена ниже",
      "kicker": "ХУК",
      "inserts": [
        { "kind": "quotes", "kicker": "КОТИРОВКИ", "title": "Рынок на 15 октября",
          "rows": [["BTC", "81 174", "−2,38"]], "anchor": "биткоин", "side": "r" }
      ]
    }
  }
}
```

* `inserts` сопоставляются по `kind` в порядке появления в блоке;
* `anchor` — фраза, по которой ищется момент в речи (иначе берутся стандартные
  метки генератора);
* всё, что не задано, генерируется как раньше — файл нужен для «доводки до
  литературного», а не для ручной сборки каждого кадра.

Для прогона `2026-10-15-крипта` такой файл написан целиком: 12 блоков, 39 вставок.

### 3. Запрет многоточия

`TextMetrics` измеряет строку настоящим Inter (`PIL.ImageFont.getlength`) против
ширины, которая у карточки реально есть. Если строка не влезает, она
**переписывается**:

1. берётся короткий авторский вариант (`alts`, например короткие подписи столбцов);
2. отбрасывается хвостовое придаточное по запятой;
3. в крайнем случае снимаются слова с конца — но только до целого слова.

Многоточие не производится ни на одном шаге, а `assert_no_ellipsis` роняет
сборку, если `…` когда-нибудь появится. Отчёт о подгонке — `copy_fit.json`.

## Приёмка

* `verify_extra.py → copy_quality`: в композиции 0 многоточий, число
  переписанных строк и источник текстов попадают в отчёт;
* `hyperframes check`: раскладка и контраст считаются по факту, а не по обещанию;
* лист кадров (`frames/`) даёт по одному кадру на каждый элемент — глазами видно,
  что именно напечатано.

## Правила, которые стоит держать

* В кадр попадает только то, что читается как фраза для зрителя. Служебные
  пометки сценария — никогда.
* Лучше короче и точнее: подгонка по ширине предпочтительнее обрезки.
* Числа берутся из сценария и не изобретаются; если диктор сказал иначе — на
  экране цифры сценария, и это отражено в отчёте §13.
* Новый ролик без файла вставок должен выглядеть прилично: авторский слой — это
  улучшение, а не условие работы.
